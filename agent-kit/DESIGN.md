# monoedge: design system for agents

> **Agent: read this whole file before you design or build anything.** It is the single source of truth for the monoedge look and feel.
> Generated by `npm run build:kit` from the live tokens and CSS. Version `0.0.0`. Do not hand-edit; edit `kit-src/` in the repo.

monoedge is an **edge-lit** design language. Surfaces are flush, quiet and dark-or-soft-grey. Structure and state are shown by **thin lines of light on the edges of things**, not by boxes, shadows, rounded cards or colour fills.

Use this kit in one of two ways:

| Mode | When | What to do |
|---|---|---|
| **A. Build with the framework** | You are making a web page or app (HTML/CSS/JS, any framework) | Copy this folder into the project, link `monoedge.css` and the scripts, write markup from section 7. Start from `examples/starter.html`. |
| **B. Apply the language only** | Another medium: slides, Figma, native app, email, print, a site on a different CSS stack | Follow sections 1 to 5 and 9. Use the token values from section 4 (`tokens.json` is machine-readable). Don't copy the CSS; reproduce the rules. |

If anything in this file contradicts your instinct about "good modern UI", **this file wins**. The common instincts (rounded cards, drop shadows, gradients, pill buttons, coloured icons) are exactly what this system rejects.

---

## 1. The idea in one minute

1. **Flush, not floating.** No cards with shadows. A *panel* is a slightly lighter flat surface with a hairline frame. Overlays are a raised (lighter) surface plus a frame plus a blurred scrim. Never a drop shadow.
2. **A control may be unboxed, but never unlocatable.** Every interactive thing shows at least one edge cue at rest (a tick, a bar, a hairline). Light *grows* on hover, focus, press and selection.
3. **Light is information.** Where the light sits says what the thing is (section 3). Brighter = more engaged.
4. **Quiet colour.** Neutral charcoal or soft grey everywhere. Colour appears only as the one accent (cyan by default) and four *signal* colours that mean something.
5. **Sharp and precise.** Radius is a *signal*, hard-capped at 4px. Nothing is ever a circle.
6. **Premium, not techy.** Geometric sans (Jost) for UI, a high-contrast serif (Cormorant Garamond) for titles and big figures. Wide-tracked small caps for labels. Generous space.

## 2. Hard rules (a design that breaks one of these is wrong)

These are decided, tested in CI, and non-negotiable. Numbers match the repo's rule list.

1. **Backgrounds are never extreme.** No pure black or white anywhere. Use the four surface steps in section 4 (canvas < panel < surface < overlay).
2. **Related items share ONE panel.** Tabs and rails sit in one framed group. Dividers *between* items are detached (they do not touch the frame) and visible even when unlit. Where there is no group there is no panel: bare canvas.
3. **Light propagates from the selected item.** Its leading edge (top for tabs, start edge for rails) is the source; attached outer edges carry light fading away from it. Detached dividers become their own source, a centred bar fading at both ends, lit toward the selected side.
4. **Every alert lights its full perimeter** (info, ok, warn, err). Severity is **colour + glyph**, never colour alone. A critical *decision* dialog lights top, left and right only; the bottom edge stays dark so the options are readable.
5. **Notifications are a notch:** top-centre, opening from the middle outward, only the bottom edge lit and it appears first. One at a time. About 1.5s in, 0.8s out, 4.7s dwell.
6. **Opposing actions** (`.me-pair`): only the "hot" one wears the full perimeter; the safe action is hot at rest; heat follows the click.
7. **Busy buttons:** the edge light orbits the perimeter from top-left, anticlockwise. Icon buttons do not orbit.
8. **Checkbox and radio are plain** (box with a tick; square with a square dot; no light). The **switch** is the only selection control that emits light, and its light trails back across the track when on.
9. **Row hover differs from selected:** hover = faint short bar + faint wash; selected = bright wider bar + gradient wash.
10. **Badges:** only a *status* gets a fill (`.me-badge--fill`: solid block, reversed text). Roles, counts, due dates are plain unboxed text with no brackets and no tint (unless it is a warning). Status beacons are a **vertical light-bar, never a dot**.
11. **Signal colours are fixed:** red = critical, amber = warning, green = ok, sky blue = notice. **No other hues** exist in the system besides the accent. No purple gradients, no rainbow charts.
12. **Light placement vocabulary:** buttons light the **top**; fields light the **sides** (ticks); switches **trail**; tabs and rails per rule 3; alerts the **full perimeter**; the notch the **bottom**.
13. **Radius is capped at 4px.** Tokens: none 0 (dividers, cells, tabs, anything touching a neighbour), micro 2 (inputs, checkboxes, kbd), soft 3 (buttons, segmented, panels), float 4 (modals, menus, tooltips, notch, alerts). Nested radius = outer minus gap.
14. **No shadows on overlays.** Separation = raised surface + frame + blur scrim.
15. **Icons:** 16px grid, 1.25 stroke, square caps, mitre joins, straight segments only (no circles, no arcs, no curves), exactly one lit segment each. Never coloured icons; they inherit text colour and the lit segment takes the accent.
16. **Accessibility is part of the look** (section 9). WCAG 2.2 AA is the floor, not a stretch goal.

## 3. How light is used (the vocabulary)

| Element | Light | Rest to hover to pressed |
|---|---|---|
| Button | top edge bar (2px) | rest .2, hover .6, pressed 1 (automatic on `.me-lit` interactive controls) |
| Field (input, select, textarea) | two short vertical **ticks** at start and end; on focus a 2px bar top and bottom appears in the signal colour (second focus cue, WCAG 2.4.13) | ticks 3:1 or better at rest |
| Tab | top edge of the selected tab | detached dividers visible when unlit |
| Rail / side nav item | start edge of the selected item | collapsed rail: counts become a tiny vertical bar |
| Switch | thumb moves; light trails back across the track when on | |
| Alert | full perimeter in the signal colour | |
| Notification (notch) | bottom edge only | |
| Dialog | top edge; critical decision: top + sides | |
| Scroll thumb | 2px accent bar, appears on hover, focus or scroll, fades after about 1s | edge lights on small scrollers and always on touch |
| Chart series | the line itself is a light-bar; area fill is a faint wash under it | |

Implementation hooks you will use: add `.me-lit` to a surface and `data-lit="t"` (or `"t r l"`) to choose which edges glow; `data-lit-level` overrides the illumination level; `--lit-span` sets how far a bar spreads.

**Signal scopes.** Put `data-signal="ok|warn|err|info"` on any element and its descendants get `--sig`, `--sig-text`, `--sig-rgb`. Use `class="me-sig"` for text in the signal colour. Don't write signal colours by hand.

**Accent.** Default cyan. To rebrand, override `--accent`, `--accent-rgb`, `--accent-text`, `--accent-text-rgb` in both themes (text variant must hit 4.5:1 on panel, the base 3:1). In the source repo, derive them from one seed colour: `node scripts/derive-accent.js "<any colour>" [--write]` (it moves only lightness, only as far as needed, and the build fails if contrast drops below the gate). Don't invent a second accent.

**Density.** `data-density="compact|roomy"` on any ancestor (control height 28 / 36 / 44). On touch devices the floor is 44px automatically.

## 5. Typography, space, motion

- **UI:** Jost (`--font-ui`), weights 300 to 600. **Titles, big figures, brand:** Cormorant Garamond (`--font-display`), weights 500 to 700.
- **Base size is small on purpose: 12px / 18px, `letter-spacing: .02em`** (set by `.me`). Don't enlarge body text to "fix" it; use hierarchy (display serif titles, big stat figures, wide-tracked labels) instead.
- **Labels / meta:** small, uppercase, wide-tracked (`.me-label`). **Titles:** `.me-title` (display serif). **Big numbers:** `.me-stat-value`. **Body text:** normal case, comfortable line height. Numbers in tables right/end-aligned in `.num` columns with tabular figures (`.me-num`).
- **Spacing** is a 4px scale: 4, 8, 12, 16, 24, 32 (`--space-*`). Panel padding is 16 to 24; gaps between sections 24.
- **Motion:** `--ease` and `--dur`. Everything honours `prefers-reduced-motion` (no orbit, no fades; states still change). Loading uses the orbiting edge light or `.me-skeleton`, never a spinner circle.
- **Direction:** the layout is RTL-safe. Use logical CSS (`margin-inline-start`, `inset-inline-end`, `text-align: start`); never `left`/`right`/`text-align:left`. Mirror direction-bearing icons with `data-flip`. Multiply horizontal offsets by `var(--dir)`.

## 6. Using the framework (Mode A)

```html
<!doctype html>
<html lang="en" data-theme="dark">          <!-- or data-theme="light"; omit to follow dark -->
<head>
  <meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1">
  <link rel="stylesheet" href="monoedge.css">
</head>
<body class="me">                          <!-- REQUIRED: .me is the scope class; base type, canvas colour, box-sizing, reduced-motion, print and form-font rules all hang off it -->
  <script src="monoedge-icons.js"></script>   <!-- first child of body: injects the icon sprite -->
  <!-- your page -->
  <script src="monoedge.js"></script>          <!-- optional behaviour (charts, pickers, palette...) -->
  <script src="monoedge-elements.js"></script> <!-- optional <me-*> custom elements -->
</body>
</html>
```

- **Put `class="me"` on `<body>`** (or on one root element that wraps all UI). Without it the framework's base type, canvas background, reduced-motion handling and print styles do not apply. Popovers and dialogs must live inside it.
- Keep the folder layout: `monoedge.css` imports `fonts/fonts.css`, `dist/tokens.css`, `dist/fallback.css`. Don't move them apart.
- **Cascade layers:** `reset < tokens < base < components < utilities`. Your own *un-layered* CSS automatically beats the framework with no specificity fights. Prefer overriding **tokens** (`:root{ --accent:... }`) over overriding components.
- **No build step is required.** The CSS and JS work from `file://`. JS is only needed for charts, date/combobox/palette/upload/tree/toolbar/wizard/scroll/split, and the custom elements. Buttons, fields, tabs (styling), tables, alerts, badges, panels, modals (`<dialog>`) are CSS only.
- **Theme switch:** set `data-theme` on `<html>`. The page follows nothing implicitly; decide, or read `prefers-color-scheme` yourself and set it.
- **Framework adapters:** Tailwind: use `tailwind.preset.js`. React/Vue/Svelte: render the same markup; for the interactive widgets either call the `ME.*` helpers in an effect or use the `<me-*>` elements (React 19 passes props to custom elements; older React: set properties through a ref).
- **Never edit `monoedge.css` or `dist/*`.** Override with tokens or un-layered CSS.

## 7. Component catalogue (canonical markup)

Class prefix `me-`. Modifiers use `--`. Signal via `data-signal`. All of these are exercised in the repo's `garden.html`, pass axe in dark and light, and are covered by tests.

**Layout primitives.** `.me-stack` (vertical flow, gap), `.me-row` (horizontal, wraps), `.me-grid` (auto-fit cells, `style="--cell-min:200px"`), `.me-panel` (flat framed surface), `.me-rule` (hairline divider), `.me-list` (grouped single panel of rows). Responsive behaviour is by container query, not viewport media query: wrap a region and it adapts to its own width.

**Button.**
```html
<button class="me-btn">Default</button>
<button class="me-btn me-btn--primary">Primary</button>      <!-- one per view -->
<button class="me-btn me-btn--ghost">Quiet</button>
<button class="me-btn me-btn--danger">Remove</button>
<button class="me-btn me-btn--ghost me-btn--icon" aria-label="Close"><svg class="me-ico" aria-hidden="true"><use href="#i-close"/></svg></button>
<button class="me-btn" aria-busy="true">Saving</button>        <!-- orbiting edge light -->
<div class="me-pair" role="group" aria-label="Frost response"><button class="me-btn me-btn--danger">Ignore</button><button class="me-btn" data-hot>Cover</button></div>
```
Icon-only buttons **must** have `aria-label`.

**Field (input, select, textarea).**
```html
<div class="me-field">
  <label class="me-label" for="n">Name</label>
  <div class="me-anchor"><input id="n" placeholder="e.g. North 2"></div>      <!-- .me-anchor draws the ticks -->
  <span class="me-hint">Shown under the field.</span>
  <span class="me-error-msg">Shown only when the field has data-signal="err".</span>
</div>
<div class="me-anchor"><select id="s"><option>North</option></select><span class="me-select-caret"></span></div>
```
Error state: set `data-signal="err"` on the `.me-field` (shows `.me-error-msg` with a glyph and turns the ticks red) and also set `aria-invalid="true"` on the input. Always a visible `<label>`.

**Choice controls.**
```html
<label class="me-choice"><input type="checkbox" class="me-check"> Keep me signed in</label>
<label class="me-choice"><input type="radio" class="me-radio" name="sun"> Full</label>
<span class="me-label" id="a">Auto</span><button class="me-switch" role="switch" aria-checked="true" aria-labelledby="a"></button>
<div class="me-segmented" role="group" aria-label="Theme"><button aria-pressed="true">Dark</button><button aria-pressed="false">Light</button></div>
<input type="range" class="me-slider">
```

**Alert** (inline) and **notification** (notch).
```html
<div class="me-alert" data-signal="warn" role="alert"><span class="me-glyph">!</span><div><div class="me-alert-title">Frost warning</div>Cover beds tonight.</div></div>
<div class="me-toasts" aria-live="polite"></div>   <!-- append one .me-alert role=status here at a time; add .is-out after ~4.8s -->
```
Glyphs: `✓` ok, `!` warn, `✕` err, `i` info.

**Badge, status, tag, kbd.**
```html
<span class="me-badge">12</span>                         <!-- plain text, no box -->
<span class="me-badge me-badge--fill" data-signal="ok">Active</span>   <!-- STATUS only gets a fill -->
<span class="me-tag">raised</span>  <kbd class="me-kbd">Ctrl K</kbd>
```

**Stat card, meter, chart.**
```html
<div class="me-stat" data-signal="warn"><span class="me-label">Soil moisture</span><span class="me-stat-value me-sig">41%</span><span class="me-delta">▼ 6 pts</span><span class="me-spark" id="sp" role="img" aria-label="Falling"></span></div>
<div class="me-meter" style="--v:62%" role="progressbar" aria-valuenow="62" aria-valuemin="0" aria-valuemax="100" aria-label="Done"><i></i></div>
```
Charts: `ME.chart(host, [1,3,2,4], { labels:[...], unit:' L', axis:true, step:false, spark:false, table:true })` or `<me-chart values="[1,3,2]" labels='["a","b","c"]' axis table label="Water use">`. Several lines: `ME.chart(host, [{name:'Now',data:[...]},{name:'Before',data:[...],alt:true}])`. Line/area/step/sparkline only; charts are accessible (visually hidden data table, titled points). **Series colours are the accent or a signal, never a palette.**

**Table.**
```html
<div class="me-table-wrap" data-me-scroll>
  <table class="me-table"><thead><tr><th class="me-label" scope="col">Name</th><th class="me-label num" scope="col">Moisture</th></tr></thead>
  <tbody><tr><td>North 1</td><td class="num">62%</td></tr></tbody></table>
</div>
```
Always `scope="col"`, always wrap in `.me-table-wrap` (scroll + lit thumb). Row hover and selected are different (rule 9). Empty state: `<div class="me-empty">`.

**Tabs, breadcrumbs, pager, steps, accordion.**
```html
<div class="me-tabs" role="tablist" aria-label="Groups"><button class="me-tab" role="tab" aria-selected="true" id="t1" aria-controls="p1">All</button><button class="me-tab" role="tab" aria-selected="false" tabindex="-1">Admins</button></div>
<ol class="me-crumbs" aria-label="Breadcrumb"><li><a href="#">Home</a></li><li aria-current="page">Beds</li></ol>
<nav class="me-pager" aria-label="Pages"></nav>
<ol class="me-steps" aria-label="Steps"><li><span>Location</span></li><li><span>Crop</span></li></ol>   <!-- ME.wizard(root) -->
<div class="me-accordion me-panel"><details><summary>Question</summary><div class="me-acc-body">Answer</div></details></div>
```
The framework styles tabs and fades a clipped strip (`ME.tabsOverflow`, wired by `ME.init`), but **you** write selection and arrow-key handling (WAI-ARIA tabs pattern: roving `tabindex`, `aria-selected`). Use `ME.nextKey(e)` / `ME.prevKey(e)` so the arrows follow the reading direction. Plain `<button>`s inside `.me-tabs` are styled as tabs; `.me-tab` is optional.

**App shell.** Side navigation `nav.me-side` containing `.me-side-set` groups, each `.me-label` + `.me-rail` of buttons `<button aria-current="page"><svg class="me-ico">..</svg><span class="me-side-txt">Overview</span><span class="me-badge">3</span></button>`, and a `.me-side-foot` icon group. It collapses to an icon rail with hover tags. Top bar: `header.me-nav` with `.me-tabs` and `.me-nav-end`. Page heading: `.me-title` plus a `.me-dim` subtitle.

**Dialog.** Native `<dialog>` only.
```html
<dialog class="me-modal me-lit" data-lit="t" aria-labelledby="h">
  <div class="me-modal-head"><span class="me-title" id="h">Add bed</span><button class="me-btn me-btn--ghost me-btn--icon" aria-label="Close" data-close><svg class="me-ico" aria-hidden="true"><use href="#i-close"/></svg></button></div>
  <div class="me-modal-body me-stack" data-me-scroll>...</div>
  <div class="me-split"><button data-c="l" aria-pressed="false">Save</button><button data-c="r" aria-pressed="false">Cancel</button></div>   <!-- ME.split(el) -->
</dialog>
```
Destructive confirmation: `data-signal="err" data-lit="t r l"`, title with `.me-sig`, and the safe option `autofocus` (the split footer's right side). Open with `dlg.showModal()`.

**Menu / popover.** `<ul class="me-menu me-lit" role="menu" data-lit="t"><li role="none"><button class="me-menu-item" role="menuitem">..</button></li></ul>` (destructive item: `data-signal="err"`). Pickers and listboxes use the Popover API; the JS mounts them for you.

## 8. Page recipes

- **Sign-in:** two columns on wide containers: a hero side (display serif brand, one line of copy, no stock imagery) and a form side (`.me-field`s, one `.me-btn--primary`, "or continue with" row using `.me-rule` + `.me-label`, alternatives in a `.me-list`). Theme toggle in the corner as `.me-segmented`.
- **Dashboard / overview:** page head (`.me-title` + subtitle + one primary action) then, in order: alerts that need action, a `.me-grid` of `.me-stat`s (1 headline number each, a delta, a sparkline), then `.me-panel`s with a `.me-label` heading holding a chart or list. Max one primary button per view.
- **List + detail (CRUD):** filter `.me-segmented`, search field, `.me-table` in `.me-table-wrap`, `.me-pager`; create/edit in a `<dialog>` with a split footer; delete asks for confirmation in a critical dialog.
- **Form:** one column, `max-width` about 340 to 480px per field, labels above, hint below, errors replace the hint and name the fix ("Choose a crop to continue"), not just "Invalid". Primary button last, aligned to the end.
- **Settings:** `.me-tabs` or a rail, one panel per group, switches for immediate-effect toggles, buttons for committed changes.
- **Marketing / landing page:** same language. Large Cormorant headlines, wide-tracked labels, hairline rules between sections, flush full-bleed bands in `canvas`/`panel` tones, a single accent-lit call to action. No gradients, hero illustrations in flat line style only, no stock-photo cards.
- **Empty / loading / error:** `.me-empty` with a sentence and the next action; `.me-skeleton` bars (never a spinner); inline `.me-alert` for failures with a retry button.

## 9. Accessibility requirements (the floor)

- Text 4.5:1, non-text and control boundaries 3:1 (the token build **fails** if a pair drops below; do not override a colour without re-running `npm run build:tokens`).
- Visible focus on everything; fields get a second cue (bars) for WCAG 2.4.13. Never `outline: none` without a replacement.
- Target size: 24px minimum, 44px on touch (automatic). Icon-only controls need `aria-label`.
- Never colour alone: pair it with a glyph, word or position.
- Native elements first (`<button>`, `<dialog>`, `<details>`, `<table>`), ARIA Authoring Practices patterns for the rest (tabs, menu, listbox, switch, tree, toolbar).
- `prefers-reduced-motion`, `prefers-contrast`, `forced-colors` (scroll bars come back natively), RTL and 200% zoom are all handled; keep them working.
- Every chart has a text equivalent (`table` option or `label`).

## 10. Do and don't

| Do | Don't |
|---|---|
| Flat panels with a hairline frame | Cards with box-shadow, glassmorphism, neumorphism |
| Light on one edge to show state | Filled coloured buttons for everything, gradients on surfaces |
| Cyan accent + four signal colours | Purple/indigo gradients, extra brand hues, rainbow charts |
| Radius 0 to 4px | Pill buttons, circles, avatars-as-circles, round progress rings |
| Straight-segment line icons | Rounded/duotone/filled icon packs, emoji as icons |
| Status badge = filled block; the rest plain text | Brackets/boxes around every label, dot beacons |
| `.me-label`s: small, uppercase, wide-tracked | ALL-CAPS body copy; bold everywhere |
| Dark charcoal (`#14171d`) or soft grey (`#dadee3`) | `#000` or `#fff` backgrounds |
| One primary button per view | Several competing primaries |
| Skeleton bars, orbiting edge light | Spinners |
| Tokens and un-layered overrides | `!important`, editing framework files |
